# Working in this project

Start with `README.md` and, if they exist, `GROUND-RULES.md` and `CURRENT.md`. Treat the templates as options, not a requirement to create every file. Treat ground rules as a human-owned anchor, not a status file; update current state within your authority. Follow the user's instructions; flag ambiguity or conflicts rather than issuing team-wide directives.

For substantive work, explain the question, evidence, uncertainty and next useful step in terms a person can check. Link to the relevant artifact. Keep updates brief; do not require acknowledgments or repeatedly reread an entire history. Parallelize independent questions when useful, then account for integration cost.

Run the relevant checks; distinguish smoke tests from evidence of an effect. Preserve the exact code, input and output references needed to reproduce a result. Before calling something a candidate or submission, check that the reviewed revision and actual artifact match. Do not claim an unrun test or a conclusive negative result.
